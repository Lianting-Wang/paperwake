# 电池运行的失败处理

正常模式所有路径都应在总预算内结束并请求安全关机。PiSugar、校时、server、采集、显示、闹钟、磁盘和通知失败都记录在本轮状态。实际断电只能通过硬件/新启动证据验证，不能由上报意图推断。

## 关机判定

- 本地 `/boot/DEBUG` 或 `/boot/firmware/DEBUG` 存在：本轮完成后留机。
- 本轮 server 成功返回严格布尔 `debug=true`：后续显示/报告失败也留机。
- 没有本地标记且本轮未取得远程 true：关机，包括无法连接 server。
- 远程 debug 永不从 state、队列、上一轮配置或缓存恢复，不会创建本地 DEBUG。
- 低电量跳过联网和采集，仍安排闹钟并按本地 DEBUG/关机策略收尾。

初次报到失败时保留屏幕，不执行正常显示任务；本地 DEBUG 下也只结束本轮，没有无限重试或后台轮询。已经连上但内容无效时记录错误，不覆盖旧画面；有效的远程 debug 独立保留。

有故障的远程维护周期以退出码 10 正常收尾，unit 接受该状态。无远程维护时故障返回 1。systemd 仍对崩溃、信号和 300 秒超时触发独立关机兜底，仅本地 DEBUG 可阻止该兜底。

## 时间与持久化

应用总预算 240 秒，所有等待采用单调时钟。工作阶段预留 server 报告、通知、可选错误显示、关机和持久化预算。报告队列整体共享一次最多 30 秒期限。预算不足直接跳过可选工作，不能因新错误重新开始计时。

PiSugar 默认等待就绪最多 45 秒，单次通信最多尝试 5 次；初始化、可信校时、RTC 写回或闹钟读回失败后，在原工作期限内最多进行 5 轮恢复。任务预留 60 秒给后续 RTC 恢复，恢复不会重启预算或放宽可信时间校验；全部失败后仍关机。Wi-Fi 最多尝试 3 次，共用 6 秒；电子纸每轮只刷新一次。

唤醒时间优先使用本轮服务器计划，离线使用本地缓存的多个未来时点与完整每日规则，缓存无效时回退配置时间表。缓存永不保存远程 debug。

HTTP 失败先写本地状态/报告队列，下次连接成功后补报。队列有界，丢弃计数可追踪；磁盘故障不能绕过关机。server 按 device/event/phase 去重并防止历史报告覆盖较新的设备状态。普通最终报告在请求关机之前发送，仅表示关机意图；下轮 previous 摘要携带真实调用结果，关机请求失败另外排队 outcome。

状态包含 time_trusted、失败阶段、恢复标记、电池、显示版本、指标、闹钟、server/报告状态与关机调用结果。可信时间校准后按单调耗时修正 started_at；finished_at 含收尾。JSON 使用 fsync 与同目录原子替换。

## 可选通知与显示钩子

`notification.command` 和 `failure_display.command` 均为参数数组，通过 JSON stdin 接收本轮状态，不经过 Shell；默认空，不发送外部消息。通知最多 5 次、单次最多 5 秒、总 20 秒（按剩余次数分配尝试时长），含退避清理；通知失败不再次通知自身。未配置明确标记 not_configured。错误展示默认关闭，失败不阻止关机。

子进程使用独立进程组，期限到后 TERM/KILL 并回收；systemd KillMode=control-group 为独立兜底。服务器异常页只展示报告错误、超期未报到和维护状态，不主动发送外部通知。

# 已知问题与后续工作

以下问题仍需处理。硬件相关修复应在设备上验证完整的关机和自动唤醒流程。

2026-10-22 的代码审查、Pi 只读检查与隔离复现见 [项目与 Pi 运行审查](audit-2026-10-22.md)，包含问题优先级、证据、建议流程和验收顺序。本次仅增加审查记录，未修复运行源码或改动设备。

## 优先恢复 RTC 和唤醒

2026 年 10 月 22 日查询时，系统时间已由 NTP 同步，但 PiSugar `get rtc_time` 返回 2020 年。当天 01:20 的调度日志中，`rtc_alarm_set` 返回 `I/O error (os error 5)`。电池查询正常不能证明 RTC 正常，具体硬件或软件原因仍需排查。

当前有人值守排查保留 `/boot/firmware/DEBUG` 或 `/boot/DEBUG`。现有标记实际为目录；调度器只检查路径是否存在。DEBUG 是维护例外，正常电池运行应在失败通知预算耗尽后仍请求关机，见 [失败处理约定](failure-handling.md)。闹钟读回中固定的 `2000-01-01` 日期与 `rtc_time` 返回错误年份是两回事，调度器仅比较闹钟时分秒。

02:53–02:58 EDT 核验时，设备实际 `/etc/pisched/config.json` 的 `shutdown_even_if_alarm_set_failed` 为 **true**。这一行为符合随后明确的电池运行策略；仓库模板也已同步为 true。RTC 在走时但年份仍为 2020；日志还确认调度器曾将系统时间回拨到该错误日期，NTP 前跳随后触发等待超时误判，跳过 pi→RTC 同步。缺少 hwclock 另有日志错误，但尚不能证明它就是闹钟 I/O error 的根因。

## 调度程序

- **任务超时可能失效**：`run_task()` 在判断超时前阻塞于 `stdout.readline()`；无输出的子进程可能超过配置时间。终止时也未管理整个子进程组。
- **使用可跳变的系统时钟计时**：网络等待、NTP 等待和任务计时使用 `time.time()`。RTC 恢复和 NTP 校时会使时间跳变，后续应改为单调时钟。
- **错误返回不足**：闹钟设置失败后仍返回任务返回码，systemd 可能记录成功。
- **闹钟时间计算偏早**：在任务之前计算下一次唤醒。任务耗时跨过计划时点时，应在任务结束后重新计算。
- **PiSugar 服务依赖缺失**：unit 仅依赖网络，没有明确等待 PiSugar 服务/socket 就绪；健康检查失败直接退出。
- **星期过滤不完整**：`compute_next_run()` 只按每天计算。维护工具暂时拒绝 `repeat_mask` 非 127 的配置。
- **电池失败收尾未完成**：缺少共享次数/总时限的通知接口与持久化失败状态；早期退出、未捕获异常或任务阻塞可能绕过关机。通知和未来页面展示失败也不能阻止关机。

## 采集与显示

- Shell 开启 `set -euo pipefail`，RSSI 或 RTT 解析管道失败可能提前退出，后续 `NaN` 回退来不及执行。
- `epd` 后的 `|| true` 会隐藏电子纸失败；屏幕显示的 `READY` 也是固定文案。
- 底层驱动存在无超时的硬件等待循环，需要结合任务进程管理一起处理。
- 每次全屏清屏、刷新后额外等待 5 秒。需要先测量刷新与功耗，再决定是否优化。
- 网络测试地址、接口和路径分散硬编码，后续统一到配置。
- 4 bpp 下 `Paint_Clear(0xF0)` 会将两个像素填为白/黑，而非纯白；实际页面留白区域已离线复现。
- 绘图库对边界使用 `>`，允许 y 等于高度，ASan 已复现帧缓冲越界；实际尺寸的当前整页渲染未触发该越界。
- 实际运行配置未复用维护校验，字符串 `"false"` 会被转换为 true；DST 缺失/重复时间的策略未定义。
- 设备低电量提前关机阈值为 0%，DEBUG 留机或绕过关机的异常尚无电量和总时限兜底；项目日志尚未配置轮换。

## 构建与维护

构建环境固定 Debian 13 基础镜像 digest、ARM64 平台和 bcm2835 源码包校验值；APT 包仍会随时间变化，尚未达到包版本完全锁定的构建。实际编译器和 libc 版本保存在 `build/display/build-info.txt`。编译成功后仍需验证产物在屏幕上的运行。

启动配置中的省电/提速注释不能作为实测结论。`dwc2` peripheral 模式也不应直接理解为完整关闭 USB 控制器。启动配置仅作 Pi Zero 2 参考，不随发布包覆盖设备启动文件。

建议后续按 RTC/唤醒 → 超时和错误传播 → 配置统一 → 测量启动及功耗 → 扩展页面内容的顺序处理。
